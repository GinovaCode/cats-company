# Agent 执行过程中的对话（液态浅色前端）

用户目标：让执行过程成为用户能理解、能参与的对话。气泡承载具体沟通，不只给长回复增加背景。

## 对话内容规则

- 接到任务：简短确认理解，说明紧接着要做的动作。
- 有新发现：说明具体事实及对用户的影响，例如“公司已经填好了，我会保留。手机号没找到，先留空。”
- 阶段完成：说明已完成什么、接下来做什么。按有意义的里程碑发消息，避免每个字段或每个工具都发一条。
- 需要用户决策：指出缺什么、影响是什么、需要用户回答什么。失败、停止或部分完成必须按真实结果描述。
- 最终交付：简短交代结果、例外及下一步；详细内容用文件、应用或可展开详情承载。
- 消息由真实事件触发。不得定时虚构进度，不得从工具名推断成功，不把内部推理当作对用户的说明。
- 保留运行中输入、发送和停止的能力。追加指令的真实调度方式沿用平台逻辑。

## 本轮实现

`ChatMessage` 从执行记录中提取显式 `assistant_text`、`presentation_role: process` 以及已有 `AI文本:` / `_display_text_role: process` 路径产生的过程说明。液态浅色下默认显示为独立短气泡，技术细节继续可展开；完成后保留过程消息，不重复显示同一说明。

`thinking`、工具参数、原始结果和子 Agent 日志不自动转成主 Agent 对话。新增气泡仅在 `html[data-theme="liquid"]:not([data-liquid-variant="green"])` 下显示，其他主题保留原呈现。最终消息的长文、代码和表格仍能完整阅读。

执行中：最新过程消息下方显示三个点的乳白气泡，轻微交错明暗表示收到近期执行活动；减少动态效果时使用静态三点。真实完成、失败、取消或最终回复后：三点移除，状态与详情入口移到 Agent 名字下方、过程气泡上方；原有过程消息保留。关闭“显示思考”仅关闭技术详情，保留用户可读的过程说明。

正式 `MessagesView` 已接入这套呈现。过程与流式消息、输入心跳、WebSocket 连接事件驱动状态；30 秒没有新的活动时停止动画并提示“暂未收到新进展”，不推断失败或成功。断线提示暂时无法更新，重连后等待新进展。发送补充要求后显示平台送达提示，不冒充 Agent 已理解或已经开始执行。

停止请求的服务端 ACK 只显示“停止请求已送达，等待 Agent 确认”。已有 `task_status` 事件必须同时匹配话题、Agent 和任务编号才能显示“已完成 / 执行失败 / 已停止”；失败原因按服务端原文显示。没有匹配任务状态的最终文本只显示“已回复”。拒绝较早任务状态覆盖较新的状态，打开聊天或重连时读取会话摘要恢复匹配状态；无法匹配的历史记录保留为未知进展。

液态浅色下按消息 ID 更新重复快照，不增加重复气泡；最终快照替换对应流式消息，并忽略这个流已结束后迟到的增量。明确的不同任务编号不会按同一用户指令合并；同一任务在用户追加消息后发来的最终回复仍可结束对应过程展示。没有事件序号的重复流式增量无法可靠区分，前端不会按文本去重，以免删除合法的重复文字。

这次改前端呈现和事件接入，没有修改 Agent runner / 提示词 / 服务端协议。真实 Agent 若不发送明确过程说明，前端不会凭空生成具体沟通内容；已有合并消息的内容也不会按句子自动拆分。缺少任务编号或状态回执时使用保守提示，不能保证每个历史任务都能恢复精确终态。

## 本地预览

视频参考调整：等待气泡与首条回复复用组件和文字气泡，持久化终稿沿用流式消息位置。新到达的 WebSocket 正文、过程说明及带文件的说明文字都使用同一显示队列；加载的历史不播放。正常约每秒 24 个 Unicode 字素，积压超过 100 字时渐进加速，最高每秒 120 字；尾部文字由浅变深。收到最终快照后继续显示剩余队列，不能因流结束把剩余正文瞬间铺满；显示结束才恢复回复操作。真正取消、失败、离开液态浅色或开启减少动态效果时立即补齐已收到的文字。过程状态仍按真实回执变化，显示队列不代表后台仍在执行。更正正文立即显示。已消费的实时到达标记不会在重新挂载时重播，也不会给历史加载的消息新增标记。气泡按可见正文自然增长，底部阅读随动，上翻时保持位置。演示页复用正式组件，模拟事件不执行真实任务。

入口：`http://localhost:5173/chat-bubbles-demo.html`。复用正式 `ChatMessage`、`ChatComposer` 和液态背景，播放一次表格填写的四个过程事件及最终成果。

示例内容和事件播放都是本地模拟，没有调用真实 Agent、没有实际填写表格。可重播过程、停止，并在执行中追加要求。该示例没有进入生产入口依赖图。

验证：消息、消息视图和样式及文字展开共 528 项测试通过。浏览器加载正式 `MessagesView`、真实 API/WebSocket 处理代码，以隔离的模拟网络事件检查三点到流式正文的 DOM 连续性、连续逐字展开和浅色尾部、生成中隐藏操作、终稿恢复操作、长回复跟随、上翻阅读位置、过程消息、关闭思考、追加要求、停止 ACK 与取消回执的区别、断线重连、失败原因、完成后入口位置、手机宽度和其他三个主题。生产构建和拆包/precache 检查通过。浏览器验证没有调用真实 Agent 或写入真实表格；真实执行内容质量仍取决于 Agent 的过程消息。
